# Wire cost + cache observability emit path from claude CLI

## Problem

Phase 7 shipped the full cost + cache observability stack:
- `CostTracker` event subscriber + `CostRollup` dataclass + exactly-once budget alarms
- `CacheTracker` event subscriber + `cache_hit_rate()` accessor
- `render_team` dashboard + `clawteam team show` cost panel
- `apply_fallback` ladder (opus→sonnet→haiku) triggered at 80% budget
- 58+ tests + 6 integration tests

But the event emit path is **never wired under the tmux + claude-CLI architecture**:
- `CostTracker` subscribes to `ToolCallCompleted` (D-09) — never emitted
- `CacheTracker` subscribes to `ClaudeApiResponse` (D-12) — never emitted
- Both event dataclasses exist at `clawteam/events/types.py` but have zero call sites

Result: in production, `clawteam team show <team>` always displays $0 spend and unknown cache hit rate. QUALITY-12 is partially unimplemented.

## Root cause

`TmuxBackend.spawn_agent` launches `claude` CLI in a tmux window. The Anthropic API call happens inside claude CLI's process; clawteam never sees the raw API response, so it cannot populate `cache_read_tokens` / `input_tokens` / `cost_usd`.

## Proposed fix

Approach A (preferred): parse `claude --output-format stream-json` output in `clawteam/spawn/invoke.py::invoke_native_cli` (and equivalent tmux backend), extract `usage` + `cache_*_tokens`, emit `ClaudeApiResponse` + `ToolCallCompleted` to the event bus.

Approach B: rely on claude code hooks (`.claude/settings.json`) to post structured events to a local HTTP sink clawteam subscribes to.

Approach C: stdout mitm via a wrapper script around `claude` that captures stream-json before forwarding to tmux pane.

## Acceptance criteria

- `CostTracker.rollup()` returns non-zero spend after a real sprint
- `CacheTracker.cache_hit_rate()` returns measured rate after a real sprint
- `clawteam team show <team>` cost panel displays live data
- Integration test running an actual (or captured) claude sprint verifies 3 non-zero metrics

# attend CLI "Urg" column ignores question frontmatter `urgency:` field

## Repro

Drop three question files into a sprint with `urgency: 1`, `urgency: 3`, `urgency: 4`. Run `clawteam attend`. The "Urg" column shows `norm` for all three — the numeric urgency is collapsed to a single label regardless of input.

## Expected

Column should reflect the numeric urgency from frontmatter (e.g., map 1→low, 2→norm, 3→high, 4→critical) or show the raw number.

## Root cause (hypothesis)

`clawteam/attention/queue.py::AttentionItem` parses urgency but the rendering helper in the CLI falls back to a default label constant instead of mapping the numeric value. Priority score computation appears correct (q003@urgency=4+blocking and q001@urgency=3+blocking both rank 15.0, ahead of q002@urgency=1+non-blocking at 10.0) — only the display column is wrong.

## Files

- `clawteam/cli/commands.py` — attend_root renderer (around the "Top N Pending Questions" table)
- `clawteam/attention/queue.py` — AttentionItem parsing

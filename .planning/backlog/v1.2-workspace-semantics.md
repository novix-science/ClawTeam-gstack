# v1.2 — Workspace Semantics: Team is a Persistent Workspace, Not a Task Runner

## Product-model mismatch (the core insight)

`clawteam go "<goal>"` bundles three actions into one required invocation:

1. Create team
2. Start sprint with the goal
3. Launch 11 agents (with goal as initial prompt, burning turn 1)

This forces the user into a **batch-submission mental model**: "I already know what to build, one command launches the whole factory."

The real user workflow is **workspace-style**: open the team → talk to agents → decide what to build → *then* start a sprint. The difference is the same as `submit build.sh` vs. `open IDE`.

v1.1 made the workflow contract and event loop correct (the factory now actually produces output, per v1.1-MILESTONE-AUDIT). v1.2 should make the entry point match how users actually behave.

## Four surfaced problems (all rooted in the same mismatch)

### Problem 1 — "Windows first, then tile" visual jank
- **Current:** `clawteam go --tile` calls `tmux new-window` 11 times (each agent appears as a separate window over ~20s), then `tile_panes()` merges them at the end.
- **Code:** `clawteam/spawn/tmux_backend.py:186-190` (new-window loop) + `clawteam/solo.py:296-301` (tile_panes after all spawns complete).
- **Want:** First agent gets `new-window`, remaining 10 use `tmux split-window` inside the same window with `select-layout tiled` after each split → progressive pane appearance with no final "merge flash."

### Problem 2 — First-spawn always burns turn 1 on an injected goal prompt
- **Current:** `post_launch_prompt` is pushed into the claude CLI input buffer immediately after pane launch (`clawteam/spawn/tmux_backend.py:255-261`), so turn 1 is consumed before the user can type anything.
- **Existing infra already half-built:** `clawteam/spawn/keepalive.py:11-35` has `build_resume_command()` returning `["claude", "--continue"]`, used only when an agent exits and keepalive re-spawns it (`clawteam/spawn/tmux_backend.py:105-116`). Not used on initial spawn.
- **Want:** On initial spawn, check if team has a prior session; if yes, `claude --resume <session-id>`. If no, start clean claude REPL with **no** auto-injected prompt. Initial goal injection moves to `sprint start` (see Problem 4).

### Problem 3 — Persistence is half-baked; conversations don't survive re-open
- **Persisted today:**
  - Team config at `~/.clawteam/teams/<team>/config.json`
  - Sprint state under `~/.clawteam/teams/<team>/sprints/<sprint-id>/`
  - Active team pointer at `~/.clawteam/active_team`
  - tmux pane map at `~/.clawteam/teams/<team>/tmux_pane_map.json`
- **NOT persisted:**
  - agent → claude session id mapping (claude CLI writes conversations to `~/.claude/projects/<hash>/` but clawteam doesn't record which hash belongs to which agent)
  - No `clawteam resume <team>` command
  - `clawteam go --name <existing>` is **rejected** with "Team already exists" (`clawteam/solo.py:194-200`)
- **Module exists but isn't wired:** `clawteam session save/show/clear` exists per `clawteam session --help`. Confirm whether it's called from spawn path; if not, wire it in.

### Problem 4 — `go` requires a goal; users want to open the team first, think later
- **Current:** `go` takes `GOAL` as required positional arg.
- **Good news:** `clawteam launch gstack` (the underlying primitive) already has `--goal` as **optional**. The constraint lives in the `go` wrapper, not the architecture.
- **Good news:** `clawteam sprint start <team> --goal ...` exists as a standalone command.
- **Want:** A new top-level `clawteam open` command that lands the user in a live team with no goal required. Goal is provided later via `clawteam sprint start` when the user is ready.

## Proposed REQ set (7 requirements, 3 phases)

### Phase 13 — Workspace entry point (core UX shift)

| REQ | Description |
|-----|-------------|
| **WS-01** | `clawteam open [template]` command: create-or-resume a team, no goal required. If the named team exists and has a saved sprint, resume it; otherwise create a fresh idle team. |
| **WS-02** | Remove initial prompt injection from `launch` when no goal is given. Agents start as clean claude REPLs (idle, no tokens consumed until user types). Kickoff prompt injection moves to `sprint start`. |
| **WS-03** | `go` becomes a thin wrapper over `open` + `sprint start` for users who still want one-shot semantics. Documented as "advanced shortcut," not primary path. |

### Phase 14 — Session continuity

| REQ | Description |
|-----|-------------|
| **RELI-08** | On every spawn, record `agent_name → claude session id` into `~/.clawteam/teams/<team>/sessions.json`. Wire through the already-existing `clawteam session save` module instead of inventing new storage. |
| **RELI-09** | `clawteam open <existing-team>` uses `claude --resume <session-id>` per agent to restore all conversations + re-establishes tmux pane layout from `tmux_pane_map.json`. |
| **RELI-10** | Idle-mode behavior: when no active sprint, agents respond only to user messages (no polling, no automatic wake events). Ensures `open` without a goal doesn't silently burn API tokens.|

### Phase 15 — Launch visual polish

| REQ | Description |
|-----|-------------|
| **UX-05** | Progressive pane appearance: first agent uses `new-window`, agents 2–11 use `tmux split-window` + `select-layout tiled` inside the same window. No final "merge flash." |

## Out of scope for v1.2

- Multi-user / remote team sharing (stays local + single-user)
- Replacing `~/.claude/projects/` with clawteam-owned storage (claude CLI remains the session-of-record; clawteam just tracks the pointer)
- Agent model swap mid-session (keep whatever model claude CLI is configured with)
- Observability / cost tracking (delegated to Anthropic console per v1.0 decision)

## Open questions (decide during `/gsd-new-milestone`)

1. **Should `open` auto-attach to tmux like `go` does?** Probably yes with the same `--attach/--window/--tile` flags, reusing code.
2. **What's the idle-mode signal to agents?** A system prompt that says "no active task, wait for user instruction"? Or literally no prompt at all (pure REPL)?
3. **Pre-sprint conversation capture:** if the user chats with CEO in idle mode before running `sprint start`, should that pre-sprint dialogue be included as context in the kickoff, or treated as separate?
4. **Migration of existing v1.1 teams:** do we retroactively create `sessions.json` for teams that pre-date RELI-08, or only track from v1.2 spawns forward?

## Verification criteria (what "v1.2 ships" looks like)

A user should be able to do this and have it work:

```bash
# Day 1: open a team, chat with CEO to figure out what to build
clawteam open gstack -n mycrew
# → 11 panes appear progressively in ONE window, each agent is a clean claude REPL
# → user types in CEO pane: "I want to build a CSV CLI, help me scope it"
# → CEO responds; user and CEO iterate for 10 minutes

# Day 1 (later): commit to a goal, start sprint
clawteam sprint start mycrew --goal "CSV CLI tool with tests"
# → kickoff prompts go out, sprint state machine kicks in, v1.1 event loop fires

# Day 2: close laptop, reopen terminal
clawteam open mycrew
# → same 11 panes, each claude --resume <session-id> restores yesterday's dialogue
# → sprint state (phase, current task, pending artifacts) restored from ~/.clawteam
# → user picks up exactly where they left off
```

If the user can do this without thinking about it, v1.2 has shipped.

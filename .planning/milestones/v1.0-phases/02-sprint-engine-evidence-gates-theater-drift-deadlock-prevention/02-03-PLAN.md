## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted state.json → SprintState.load | attacker-controlled JSON bytes could embed oversized integers (`turn_counters`) or wildcard keys in `suppressed_topics`; pydantic validation is the boundary |
| agent writes → SprintState.turn_counters | increments happen at Transport.deliver / ArtifactStore.write hooks (Plans 02-06, 02-08); this plan only provides the schema |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 (new) | D (DoS via unbounded counter) | `SprintState.turn_counters` | accept | Counter is bounded by the per-agent forced_progress_gate (Plan 02-09) triggering at 2 consecutive no-progress turns; pathological growth is limited by sprint lifetime (hours) + agent count (11 in gstack). Pydantic validates int; Python ints are arbitrary precision but bounded practically by 32-bit machine arithmetic in counters. |
| T-02-12 (new) | T (Tampering via suppressed_topics pollution) | `SprintState.suppressed_topics` | mitigate | Only `clawteam.team.routing_policy.DefaultRoutingPolicy.decide` (Plan 02-08) writes this field; cycle-detector logic is the only code path that adds entries. The pydantic field shape `dict[str, list[str]]` narrows type; no code reflects untrusted user-supplied keys directly into the dict. |
| T-02-13 (new) | T (Tampering via status override) | `SprintState.status` | mitigate | `Literal["running","paused","completed"]` constraint in pydantic rejects any other value at model_validate — defense against JSON tampering. |
| T-02-02 (pathway) | T (Path bypass) | — | defer | No path-handling code in this plan; the Plan 01-02 `_state_path` path-validation already in clawteam/sprint/state.py is unchanged. Plan 02-10 handles the freeze-path bypass surface. |

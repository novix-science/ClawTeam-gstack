## v1.1 Goal

Close the three architectural gaps diagnosed during v1.0 UAT so `clawteam go "build X"` reliably produces a working X through 11-agent coordination:

- **Class A — state-machine teeth:** gates must block on genuine artifact absence, not just on broken gate code.
- **Class B — event-driven feedback loop:** phase completion becomes a push event, not something CEO has to deduce by polling.
- **Class C — end-to-end regression coverage:** one integration test replaces 6 rounds of manual UAT bug discovery.

### Phase 8: Workflow Contract (state-machine teeth)

**Goal:** Wire concrete phase artifact requirements into the sprint state machine so phase advance fails on genuine missing work, and agents get a named artifact error they can self-correct.

**Requirements:** RELI-01, RELI-02, RELI-03, RELI-04

**Success Criteria**:
1. `PHASE_REQUIREMENTS` maps every gstack phase to its required artifact type(s).
2. `clawteam artifact write <team> <sprint> <artifact_type>` reads stdin, validates the artifact type, persists the artifact, and emits `ArtifactPersisted`.
3. `GstackSprintPlugin.contribute_phase_requirements()` feeds those requirements into `SprintConductor` / `EvidenceGate`.
4. `clawteam sprint advance` blocks with a named missing-artifact message when required artifacts are absent.

### Phase 9: Event-driven Coordination (close the feedback loop)

**Goal:** Make phase completion push-driven by emitting task completion events and waking the leader when all current-phase tasks and artifacts are complete.

**Requirements:** EVT-01, EVT-02, EVT-03, EVT-04

**Success Criteria**:
1. `clawteam task update --status completed` emits `TaskCompleted`.
2. `PhaseCompletionWatcher` subscribes to `TaskCompleted` and detects task plus artifact completion for the current phase.
3. `wake_agent(kind="phase")` writes a clear `[wake:phase]` instruction for the leader.
4. New team launches auto-register the watcher without explicit user opt-in.

### Phase 10: UX Polish (attend / status sync)

**Goal:** Fix attend and sprint-status polish issues discovered during UAT so pending work is represented accurately in digest and status views.

**Requirements:** UX-01, UX-02, UX-03

**Success Criteria**:
1. `clawteam attend` renders numeric urgency through the existing urgency level map instead of a static label.
2. `clawteam attend --summary` shows the first H1 title from the question body as the representative title.
3. Sprint status keeps `pending_question_ids` synchronized with pending question files via watcher startup or read-time reconciliation.

### Phase 11: End-to-End Integration Test (regression shield)

**Goal:** Add one deterministic subprocess-backed integration test that exercises the full gstack sprint lifecycle and prevents another manual-UAT-only regression loop.

**Requirements:** TEST-01

**Success Criteria**:
1. `tests/integration/test_gstack_sprint_end_to_end.py` uses the subprocess spawn backend and a scripted `claude` executable mock.
2. The test drives sprint start through reflect for the expected seven-phase agent behavior.
3. Assertions cover 6 `PhaseTransition` events, 7 persisted artifacts, at least one wake per agent, and final sprint state `completed`.

### Phase 12: Documentation Refresh

**Goal:** Refresh README and architecture docs so the documented primary flow matches the v1.1 solo UX and event-driven wake model.

**Requirements:** DOC-01, DOC-02

**Success Criteria**:
1. README presents `clawteam go`, `clawteam status`, `clawteam answer`, and `clawteam stop` as the primary flow.
2. Power-user commands such as `team spawn`, `launch`, and `sprint start` are documented as escape hatches.
3. `docs/architecture/event-driven-wake.md` explains wake:task, wake:inbox, wake:phase, nudge architecture, tmux hook wiring, and adding new wake kinds.

## Success Criteria (v1.1)

The milestone is complete when all five Phases pass `/gsd-verify-phase` AND:

1. `clawteam sprint advance` cannot succeed when the current phase's required artifact is missing — gate blocks with a named-artifact error message.
2. After the last task for a phase flips to `completed` and the artifact is on disk, the leader role (CEO) receives a `[wake:phase]` within 10 seconds without polling.
3. `tests/integration/test_gstack_sprint_end_to_end.py` runs to completion in CI (subprocess backend, scripted claude mock) asserting 6 PhaseTransition events, 7 artifacts persisted, final sprint state = `completed`.
4. `clawteam attend` and `clawteam attend --summary` render correct urgency + representative titles against a fixture of 20 diverse questions.
5. `README.md` front matter demonstrates the `clawteam go` flow as the primary user entry point; power-user commands are clearly marked as such.
